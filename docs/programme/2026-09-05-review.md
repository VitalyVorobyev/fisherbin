# ScoreQuant review — 5 September 2026

This is an assessment of the checked-out project at `474e3b6`, not another task queue.
Execution order and status live in [M13 in the roadmap](../roadmap.md#m13-focused-research-and-teaching).
The review includes source/API inspection, the research registry and selected dependency closures,
all four walkthroughs, the book overview and selected chapters, a local browser inspection,
and the separate formal-proof worktree. It is not an independent proof audit of all registered
results, a new novelty search, or a fresh large-data benchmark campaign.

## Assessment

The project has a credible algorithmic core and unusually explicit statistical contracts.
The bottleneck is translation: from mathematical results to a small set of user decisions,
and from tested evidence to teaching that accurately describes what was measured.
Rewriting the solver architecture or adding more algorithms would not address this bottleneck.

Three problems reinforce each other:

1. Research rewards expansion of a branch after its practical decision has been settled.
2. Documentation rewards completeness, provenance and testability, but does not test whether a
   new reader can identify the task, assumptions, output and next step.
3. Coordination documents preserve past decisions as if they still described the current state.
   M12 says the portal is at the root; ADR 0027 subsequently puts it at `/portal/`.

The site is not devoid of useful material. Captured snippet outputs, evidence-backed numbers,
patient-level evaluation, negative results and the browser NumPy runtime are valuable assets.
The first screen nevertheless spends its space motivating binning; it does not immediately name
an input, a decision variable, a criterion and an output. Eight primary navigation destinations
plus a second Lab entry make the reader choose among publication formats before choosing a task.
This is an editorial and information-architecture diagnosis, not a measured usability study.

The geometric diagnostic used committed points, weights, labels and cell means. For each fixture
it rebuilt `I_q = sum_b W_b mu_b mu_b.T`, used `G = inverse(I_q)`, and compared Euclidean and
G-nearest means with stored labels. This is evidence for the committed fixtures, not a proof that
all future rendering is correct. A replacement should validate raw-coordinate metric bisectors
before projection and display only active cell boundaries; above two dimensions a projection
must not imply that the displayed lines completely determine assignments.

For the certificate documentation correction, for a fixed interest vector `u` and regular nuisance
block, `u.T S(I) u = min_v [u; v].T I [u; v]`. If `I <= J`, every quadratic value on the left is
bounded by its counterpart for J, hence `S(I) <= S(J)`. Log determinant is monotone on positive
definite matrices. Thus regular Schur profiling does not destroy this monotonicity. This does
not supply an implementation's singular-node policy, usable pruning bound or global DS solver.
The variational identity follows by completing the square; the underlying block-matrix algebra
is in [Boyd and Vandenberghe, Appendix A.5.5](https://web.stanford.edu/~boyd/cvxbook/bv_cvxbook.pdf).

## Library design and capability review

**Placement decision:** preserve the numerical core and task boundary. Put the next experiments in
`examples/` and research packets. Put explanatory controls and figures in `website/`. Do not
introduce a public robustness estimator, backend registry, generic optimizer or observation-level
predictor as a byproduct of this review.

The stable abstraction is already present:

`source + explicit score provider -> weighted score law -> fixed labels or a reusable score rule`.

Strictly, this quantizes observations through their scores at a reference parameter point; it
is not a discretization of parameter space itself. That distinction should be the opening
sentence of both introductory paths.

| User task | Implemented route | Guarantee or practical limit |
| --- | --- | --- |
| Assign a fixed weighted score table | `optimize_partition`, D exchange or guarded Lloyd, D or profiled Ds | Exact objective evaluations and accepted moves; terminal exchange stability only when the required scan/guard completes. Local stability is not global optimality. |
| Label future scores using full D | `fit_quantizer`, exchange/Lloyd plus verified compilation | A score-space rule; compile conditions and numerical tolerances matter. Finite training geometry does not certify population optimality. |
| Fit a reusable profiled rule | `fit_quantizer` with `SoftVoronoiConfig` and `ProfiledDOptimality` | Direct fit in a restricted geometric family, evaluated after hardening; no generic compilation of finite profiled labels. |
| Exact scalar reference | `ScalarDPConfig` with D and effective rank one | Global interval solution for the supplied finite/quadrature measure, bounded by `max_rows`; exact quadratic work is a deliberate capacity-limited exception. |
| Trace baseline | `KMeansConfig` with `NormalizedTrace` | Weighted k-means in Fisher coordinates; not an interchangeable D solver. |
| Global D check | `certify_partition` | Bounded branch-and-bound on distinct positive atoms; optimal within configured slack if complete, otherwise an outstanding bound and budget status. |
| Obtain scores | `ScoreSample`, `ObservationSample` or `IntegrationSource` plus appropriate provider | Explicit weights, schema and provenance. Bounded tensor quadrature is not arbitrary-dimensional population integration. |
| Classifier/ratio route | Ratio adapters and provider protocol | Closure diagnostics and provenance; no assertion that classifier self-information is retained true Fisher information. |
| Move a rule between runs | `Quantizer` artifact and `predict_scores` | Versioned rule and prediction round trip exist. Whole training-state persistence, services and remote execution remain separate scope. |
| Portable execution | Private JAX/NumPy adapters, shared solver mathematics | Preserve one capability table and conformance suite. Browser execution is a useful second consumer. |

The two entry points are justified, not redundant. A `Quantizer` and a fit result are also
justified: deployment does not need optimizer history. Named score schemas, finite weights,
zero-weight behavior, rank projection without a ridge, and validation-only diagnostics should
survive any simplification.

The main API improvement is discoverability. Present a compact task/criterion/solver table before
all config fields. Default full-D use needs only a score source, K and one task call; provider,
criterion and solver details can then be introduced when the question requires them. Result
reports should be taught in this order: information kind, evaluation sample, retained rank,
hard efficiency, worst-direction diagnostics, convergence/certificate status.

`PartitionResult` carries many statistics, geometry fields and solver counters. This is a future
maintenance concern, not evidence that a breaking result redesign is presently useful. Only
extract diagnostics into a separate result object after two real consumers and a migration sketch
show a benefit. Similarly, splitting `api.py` further should follow an actual coupling problem,
not a line-count target. The current declarative solver table and shared fit preparation are good.

One contract inconsistency deserves explicit documentation: the general no-quadratic-work rule
coexists with the approved capacity-limited exact scalar DP. State this exception in contributor
policy; do not replace the solver or add a second approximate implementation just to satisfy a
blanket sentence.

## Mathematical research status

The registry snapshot contains 123 claims: 57 `project_proved`, 27 `open`, 19 `bridge`,
12 `counterexample`, 6 `literature`, 2 `measured`. Seven of the 57 project-proved entries are
audit records. These counts describe registry objects, not independent novel theorems.
`project_proved` means internally derived/audited, not externally published or machine checked.

The coherent D contribution is exact relocation algebra -> monotone finite exchange -> terminal
Mahalanobis structure -> finite-to-inductive compilation, with assumptions on positive distinct
atoms, nonempty cells, positive-definite retained information and tolerances. Restricted-class
population statements are separate. Preserve this spine, its audit, and its counterexamples.
Novelty is still qualified by the existing targeted literature record; this review did not
establish priority or publication readiness.

The DS branch has produced useful limits: finite profiled labels need not have the desired
geometry; a regular exhibited saddle can close a particular finite certificate; a nonclosed
bracket does not certify an optimum; strong duality can fail by an order-one gap; matrix-tilt
quasiconvexity fails. The projected efficient-score route is a different problem with different
nuisance-information assumptions. These results justify explicit refusal and a restricted
product boundary. They are an answer, not a reason to indefinitely promise a universal compiler.

The imbalance is visible: `KNOWN_RESULTS/05b-ds-bridge.md` has 2,304 of 3,368 known-results lines,
whereas the D chapter has 284. Before this review the DS exact-complexity packet had 281 lines
and the score-oracle packet 53. Page counts do not measure scientific value, but explain why
new sessions are drawn back into DS detail.

The highest-value next question is:

> Given a frozen rule fitted using estimated scores, what retained true-score information can
> we estimate on an independent sample, and with which conditional uncertainty statement?

Begin with the existing analytic classifier mixture, where truth scores are available. Distinguish
fixed deployed labels, changing score values under those labels, refitting the rule, and moving
boundaries. The first does not require solving the last. Keep score-proxy information, true-score
information, representation loss and quantization loss separate. A useful result may be a bound,
an estimator with stated assumptions, a counterexample, or a documented impossibility under
unrestricted tails/rare bins. None should be promoted directly into `src/` without deterministic
regression evidence and a second use case.

Pause exact DS bit-complexity, unrestricted criterion characterization, universal K laws and
multi-reference geometry as default next work. Keep their OP identifiers and mathematical record.
A clear application or a concrete publication decision can reactivate them.

The dependency graph needs a semantic migration: the DS practical audit is mutually connected
through `dependencies` with the DS compile certificate, practical-solver result and exact-complexity
remainder. A compile query expands 35 nodes, including an open question via audit bookkeeping.
This does not establish circular proof. Mathematical prerequisites should be acyclic; audit,
evidence and related-open-question edges need distinct meaning. Migration requires checking each
edge and regenerating indexes, not changing truth statuses to make a graph check pass.

## Four walkthroughs with four distinct teaching jobs

These are four applications, not four disjoint API input routes. FlowCyt and HEP both use estimated
ratios; Michelson is analytic; the synthetic mixture provides a truth-score check. A route taxonomy
should not force an artificial one-to-one mapping.

| Page and proposed order | Short problem statement | Main lesson | Required interactive experiment |
| --- | --- | --- | --- |
| Michelson | At a fixed reference fringe law, assign photon positions to K counters to retain phase information while accounting for uncertain fringe frequency. | Analytic scores, local inference, nuisance profiling, physical constraints on labels. | Change K and compare equal-width labels with a score rule; show aperture positions and resulting label sets. Distinguish disjoint electronic grouping from contiguous detector segments before the result. |
| Synthetic ratios | Estimate a mixture fraction from K labels obtained through a trained classifier; compare retained true-score information with the classifier's own report. | Estimated-score provenance and failure of self-evaluation. | Choose a committed classifier rung; show surrogate and true retention on the same held-out labels. Clearly distinguish cached results from a browser refit. |
| FlowCyt | Fit K categories on reference patients and estimate population fractions in unseen patients from category counts. | Subject-level splits, downstream error, and when compression is adequate without improving inference. | Select a held-out patient and K; show composition error alongside surrogate D-efficiency. Explain why a high retention summary and a negative downstream result can coexist. |
| HEP | Choose K categories for signal-strength inference with a floating tau-energy-scale nuisance using weighted simulated events. | Joint versus profiled information, ratio construction and baseline fairness. | Compare a frozen nuisance with a profiled nuisance and matched K; show the corresponding uncertainty proxy and score provenance. State whether an external nuisance constraint is actually included. |

Every page starts with a compact contract: observation, parameters of interest, nuisance parameters,
reference point, K, admissible labels, source measure, score-oracle regime, output and evaluation
split. Then one plain-language question, one figure, the minimum executable code, the result and
its interpretation. Move acquisition details, full sweeps and licensing provenance into clearly
labelled subsections without losing attribution. Keep the limitation near the claim it limits.

Use one page pattern rather than imposing the same scientific story on all four pages:

1. **Problem:** two or three sentences plus the compact contract.
2. **Model and score:** equations and units, with the reference point visible.
3. **Binning decision:** what may be assigned together and which criterion is optimized.
4. **Run:** executable inputs, fit and output; no undefined arrays or unexplained provider magic.
5. **Evaluate:** held-out hard labels, matching baseline, information kind, downstream quantity.
6. **Explore:** one control changes one scientific question, with reset and a static fallback.
7. **Interpret:** where this result applies, failure/refusal case and a direct theory/reference link.

For the portal opening, an appropriate draft is:

> ScoreQuant groups observations into a fixed number of labels for parameter estimation.
> You supply scores at a reference model point, or a model that computes them. The library
> optimizes a fixed sample partition or fits a rule for future scores, and reports the
> information retained by the hard labels.

Follow immediately with the two task choices and a small labelled figure. Locality, surrogate
provenance and local-versus-global optimization must be accessible beside the relevant result,
not turned into a long manifesto about honesty.

## Keep, remove, defer

**Keep:** the two task APIs; provider/source separation; named schema and provenance; numerical
invariants; exact counterexamples; generated evidence; independent proof audits; the 1D-first book;
four application programs; lazy browser runtime; negative FlowCyt result; stable URLs.

**Remove from the default reader path:** repeated motivation essays; commentary about how honest the
site is; unqualified “optimal”; scenario codenames as chart labels; a claim registry as the first
research explanation; Blog and Benchmarks as equal-priority onboarding choices; “live” labels for
precomputed fixtures. Keep technical provenance one explicit disclosure/link away.

**Retire from scheduling:** closed programme prompts, fixed model-brand delegation ladders, a new
manuscript version after every arc, and treating every residual OP as active work. Historical
packets stay as records. The coordinator may read decisive source directly; delegation is for
independent bounded reads and audits, not a requirement to route every grep through another agent.

**Defer:** wholesale Docusaurus/MkDocs migration; a new dashboard framework; more solvers;
large-scale global certification; universal DS compilation; generic confidence intervals; a
large formalization platform. Do not delete proof files or fixtures to make the repository smaller.

Keep ADR 0027's URL topology during the content work. A later routing decision should follow a
successful content pilot, not precede it. The long-term reader navigation can be Get started,
Examples, Theory, API, Research, with Lab attached to examples and benchmark/blog material under
secondary navigation. This is navigation design, not a request to move URLs today.
