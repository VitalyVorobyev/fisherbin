# The claim record

*Who this is for: a reader following a claim id from one of the other pages, or checking a statement word for word.*

Below are the published claims, one entry each, rendered from the registry rather than retyped. Each
entry gives the exact statement, the kind of statement it is, which of the
[three questions](/research/the-problem) it answers, and the published claims it depends on.
[Reading the claim record](/research/reading-the-claim-record) explains what each field means and
what the labels do and do not assert.

Two things this page is not. It is not the whole registry — a claim appears here only when its id
has been added to an explicit publication allowlist, so absence means unpublished, not refuted. And
it is not the proof: statements are verbatim, but each one's proof, assumptions in full, audit
record and boundary examples live in the registry entry itself.

One naming quirk worth knowing before you read: a few ids begin with `OPEN-` and nonetheless carry
the status *project proved*. Those are questions that were opened, worked on, and answered under
stated conditions; the id was kept stable so that earlier references still resolve. Read the status
field, not the prefix.

## Proved in the project

Statements proved inside the project. Most were independently re-derived and attacked in a recorded
audit before being registered; where an audit hardened the assumptions, the registry entry carries
the hardened version.

## Counterexamples

Exact examples showing that a plausible statement is false. Most are verified in exact rational
arithmetic and carry a regression test. Several are wired into the library as refusal messages —
see [how the API names each result](/research/api-and-theorems).

<ClaimGroup status="counterexample" />

answer is discussed in [what is still open](/research/what-is-still-open).
