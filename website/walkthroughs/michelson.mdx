# Detector segments for an interferometer phase

*Who this is for: an experimentalist who reads out a fringe pattern through a small number of
detector segments, and wants to know whether equal segments are quietly costing them phase
precision. The page follows the order every lesson follows: problem, model and score, binning
decision, run, evaluation, one experiment, interpretation.*

## 1. The problem

A Michelson interferometer turns a path-length difference into a fringe pattern, and the quantity
of interest is the fringe phase. The detector does not report where each photon landed; it
reports one count per segment, and everything downstream is built on those counts. The fringe
frequency is never exactly what the nominal wavenumber says, and over a short baseline a small
phase offset and a slightly wrong frequency produce almost the same pattern, so the fit must let
the frequency float. That is the classic confounding of interferometric metrology, stated here
as a nuisance parameter rather than waved at.

So the question is this: given K counters, and given that the fringe frequency will float alongside
the phase, which aperture positions should each counter collect from? One word about words: the page
says *counters* where the library says *bins* or *cells* and the code says `n_bins`. They are the
same K labels.

## 2. The model and its score

Conditioned on the photon count, the arrival law over $m$ whole fringes is the fringe shape

$$
p(u \mid \varphi, \epsilon) \;\propto\; 1 + V \cos\big((1+\epsilon)\,u + \varphi\big),
\qquad u \in [0, 2\pi m),
$$

with visibility $V$ fixed and known (here {f("visibility")}, over {f("fringes")} fringes), the
phase $\varphi$ the parameter of interest and $\epsilon$ the nuisance. Over whole fringes the
normaliser $Z = \int (1 + V\cos(u + \varphi))\,du$ equals the interval length at $\epsilon_0 = 0$,
so $\partial_\varphi \log Z = 0$ while $\partial_\epsilon \log Z = V\cos\varphi_0$ does not
vanish. At the reference point the conditional score is therefore closed-form:

$$
s_\varphi(u) = \frac{-V \sin u}{1 + V\cos u},
\qquad
s_\epsilon(u) = u\, s_\varphi(u) - V .
$$

Two columns, and it is worth being clear what each one is. The `phase` column is how much a photon
at fringe phase $u$ tells you about the phase: largest on the steep flanks of the fringe, zero at
the crests and troughs, which is the familiar statement that a fringe carries phase information
where it is *changing*, not where it is bright. The `fringe_frequency` column is the same quantity
multiplied by $u$, minus $V$. That constant is not a centering convenience: it is the derivative of
the normaliser, and it is what makes $E[s_\epsilon] = 0$ hold exactly. Dropping it would leave a
column with nonzero mean and a wrong information matrix. Scores are never centred in this library,
and this is the cleanest case of why: the origin is fixed by the physics, not by preference.

Because the model is exact, the study goes through the analytic door. `ScoreFunction` wraps the
callback and declares what it is, `kind="exact"` and the point the derivatives were taken at, so
everything downstream knows it is working with an exact quantity.

```python
import numpy as np

import scorequant as sq

EXECUTION = sq.ExecutionConfig(backend="numpy", precision="float64", device="cpu")

VISIBILITY = 0.6
FRINGES = 4
U_MAX = 2.0 * np.pi * FRINGES

SCHEMA = sq.ScoreSchema(("phase", "fringe_frequency"))
INTEREST = SCHEMA.select("phase")


def fringe_density(observations):
    """The normalized one-photon arrival law along the fringe coordinate."""
    u = np.asarray(observations)[:, 0]
    return (1.0 + VISIBILITY * np.cos(u)) / U_MAX


def michelson_score(observations):
    """Sensitivity to (phase, fringe_frequency) at the reference point, in closed form."""
    u = np.asarray(observations)[:, 0]
    s_phase = -VISIBILITY * np.sin(u) / (1.0 + VISIBILITY * np.cos(u))
    return np.column_stack([s_phase, u * s_phase - VISIBILITY])


provider = sq.ScoreFunction(
    michelson_score,
    provenance=sq.ScoreProvenance(kind="exact", reference_point=(0.0, 0.0)),
    schema=SCHEMA,
)
```

A callback alone cannot be fitted, and that is deliberate: a sensitivity map with no measure
attached says nothing about how often each fringe phase actually occurs. The measure is a bounded
interval with an explicit density. `IntegrationSource` turns it into a deterministic Gauss–Legendre
grid for the reusable rule, and a plain midpoint rule over the same interval gives the finite
weighted table the fixed-table task runs on. Two entries of the unbinned information have closed
forms, $I_{\varphi\varphi} = 1 - \sqrt{1 - V^2}$ and $I_{\varphi\epsilon} = \pi m\, I_{\varphi\varphi}$,
and the table reproduces both to machine precision. On every other walkthrough the library's
numbers illustrate the mathematics; here they check it.

```python
source = sq.IntegrationSource(
    [[0.0, U_MAX]],
    density=fringe_density,
    quadrature=sq.GaussLegendreConfig(order=256),
)

n_nodes = 8_000
step = U_MAX / n_nodes
u = (np.arange(n_nodes) + 0.5) * step
observations = u[:, None]
weights = fringe_density(observations) * step
scores = np.asarray(provider.score(observations, execution=EXECUTION))

information = np.asarray(sq.fisher_information(scores, weights, execution=EXECUTION))

# The two entries with closed forms, reproduced to machine precision.
assert abs(float(information[0, 0]) - (1.0 - np.sqrt(1.0 - VISIBILITY**2))) < 1e-12
assert abs(float(information[0, 1]) - float(information[0, 0]) * U_MAX / 2.0) < 1e-12
```

Every call on this page runs on the NumPy backend at double precision, declared once in
`EXECUTION` and passed explicitly. That is the portable CPU runtime rather than the JAX default,
and it runs the same shared mathematics. There is no third-party dataset and no third-party
licence: the generating program is `examples/michelson_phase.py`, and every number on this page is
read back from the evidence file it writes. The full record, with the derivation of the closed
forms and the complete sweep, is the

phase</ReferenceLink> page in the reference.

## 3. The binning decision

Three things are decided before anything runs, and the contract above already names them.

**What may be grouped together.** Any set of aperture positions may share a counter. The
optimisation is over labelings of the node table, not over cut points, so a counter that collects
from several separate stretches of the aperture is an ordinary candidate rather than a special
case. If your hardware can only realise contiguous segments, the rule this page finds is a ceiling
for what your readout could do, not a design you can copy.

**Which criterion.** `ProfiledDOptimality(interest=INTEREST)` says what is being optimised:
information about the phase *after* the fringe frequency has been profiled out. Plain
`DOptimality` optimises information about the pair, which is a different and easier question, and
the closing step shows that the difference is measurable. Picking the criterion that matches the measurement
is not a tuning knob.

**Which solver, and where it starts.** `DExchangeConfig` is the exact finite solver: it moves one
node at a time and accepts only exactly positive gains, so the result is exchange-stable by
construction. Before it runs, `efficient_score_bound` computes a certified upper bound on what any
rule with this many cells could retain from this score space, and its labels are a justified
starting point for the exchange. The bound matters twice: as the ceiling the result is judged
against in the evaluation step, and as the reason the exchange starts somewhere sensible.

## 4. The run

```python
n_bins = 6

bound = sq.efficient_score_bound(
    scores, interest=INTEREST, weights=weights, n_bins=n_bins, execution=EXECUTION
)
result = sq.optimize_partition(
    scores,
    weights=weights,
    n_bins=n_bins,
    criterion=sq.ProfiledDOptimality(interest=INTEREST),
    config=sq.DExchangeConfig(seed=4),
    initial_labels=bound.labels,
    execution=EXECUTION,
)


def profiled_retention(labels, n_bins):
    """Phase information retained, against the unbinned profiled ceiling."""
    return float(
        sq.profiled_information_report(
            scores,
            labels,
            interest=INTEREST,
            weights=weights,
            n_bins=n_bins,
            schema=SCHEMA,
            execution=EXECUTION,
        ).geometric_mean_retention
    )


def equal_width_labels(n_bins):
    """The naive readout: equal detector segments across the aperture."""
    return np.digitize(u, np.linspace(0.0, U_MAX, n_bins + 1)[1:-1])


assert round(profiled_retention(np.asarray(result.labels), n_bins), 4) == 0.9483
assert round(profiled_retention(equal_width_labels(n_bins), n_bins), 4) == 0.2054
```

The output is `result.labels`: one counter index per quadrature node, which is the readout map.
`profiled_retention` is the page's single yardstick, and it is applied to every labeling the same
way. Its `geometric_mean_retention` is the retained fraction of profiled information per parameter
of interest, combined as a geometric mean across them; with one parameter of interest, the phase,
it is simply the fraction of profiled phase information the labels keep. What the run reports:

The fitted rule is not a segmentation of the aperture in the sense a detector designer would mean.
The sensitivity of a photon depends on its position only through its phase within a fringe, so one
cell of the fitted rule pulls back to one interval *per fringe*. Laid out along the aperture the
result is a comb, several intervals per counter, each counter collecting from a repeating set of
positions: the compiled plain-D rule occupies {f("combRuns")} intervals for {f("bins")} counters,
and the sixth step draws the profiled partition's intervals at every budget. That is exactly the
disjoint label class the contract
admitted, and it is the page's most transferable point: when the physics is periodic, the
information-optimal readout is periodic, and a contiguous segmentation is fighting the model
rather than following it.

Two rows of that table are the lesson. At {f("sweepBinsLow")} counters equal segments retain
{f("equalWidthRetentionAtFour")}: four equal segments over four whole fringes make each segment
exactly one period, so by periodicity every segment sees the same average photon and the counts
carry no phase information at all. At {f("sweepBinsTen")} counters equal segments retain
{f("equalWidthRetentionAtTen")}, which is *worse* than the {f("equalWidthRetentionAtEight")} of
{f("sweepBinsEight")}: ten segments over four fringes is two and a half per fringe, which aliases
again, so buying more counters made the measurement worse. Both are the same effect, an equal
segmentation beating against the fringe period, and the general warning is that refining a
partition helps only when the refinement genuinely subdivides the old cells. An equal-width rule at
a new segment count does not subdivide the old one; it is a different rule that happens to have more
cells. The fitted rule, by contrast, improves along the sweep and stays on or near the certified
ceiling at every budget.

## 7. What it means

**Where this applies.** Whenever the physics is periodic and the readout is free to be periodic
too: a periodic mask, a modulo-addressed segmented detector, an electronic grouping of channels.
The result is a design ceiling for hardware that can only realise contiguous segments, and a design
for hardware that cannot tell the difference. The profiling cost, {f("costOfProfiling")} of the
phase information before any binning, is the part no readout can recover; the segmentation decides
how much of the remainder survives.

**Plain D is not the phase criterion, and the difference is measurable.** At
{f("sweepBinsLow")} counters a plain-D partition of the same table retains
{f("dOptimalRetentionAtFour")} of the phase information against the profiled partition's
{f("profiledRetentionAtFour")}; at {f("sweepBinsHeadline")} it is {f("dOptimalRetentionAtSix")}
against {f("profiledRetentionAtSix")}. Plain D is not misbehaving; it is optimal for the pair of
parameters, which is a different question from the one an interferometer asks.

**The library refuses to compile the profiled rule, and the refusal is a result.** A D-optimal
partition that is exchange-stable can be turned into a reusable rule, a distance computation that
labels new photons without refitting. A finite profiled partition cannot, and asking produces an
error rather than an approximation:

```python
d_partition = sq.optimize_partition(
    scores,
    weights=weights,
    n_bins=n_bins,
    criterion=sq.DOptimality(),
    config=sq.DExchangeConfig(seed=4),
    execution=EXECUTION,
)
assert d_partition.exchange_stable is True
compiled = d_partition.compile_quantizer(execution=EXECUTION)

try:
    result.compile_quantizer(execution=EXECUTION)
    raise AssertionError("a profiled partition must refuse to compile")
except sq.RefusalError as error:
    refusal = str(error)

assert refusal.endswith("[CE-DS-GLOBAL-GEOMETRY-001]")
```

The message is <code>{f("refusalMessage")}</code>. That is a theorem-backed refusal rather than a
missing feature: the geometry that makes a stable D-optimal partition equivalent to a distance rule
does not hold for the profiled criterion, so there is no rule to compile into. The compiled plain-D
rule, scored on a fresh quadrature sample it never saw, retains {f("compiledTestRetention")} of the
overall (both-parameter) information, which is the one held-out number on this page. The route to
a reusable profiled rule is to fit one explicitly, which is what the source route is for:

```python
d_rule = sq.fit_quantizer(
    source,
    provider=provider,
    n_bins=n_bins,
    criterion=sq.DOptimality(),
    config=sq.DExchangeConfig(seed=4),
    execution=EXECUTION,
)
ds_rule = sq.fit_quantizer(
    source,
    provider=provider,
    n_bins=n_bins,
    criterion=sq.ProfiledDOptimality(interest=INTEREST),
    config=sq.SoftVoronoiConfig(
        seed=4, initializer_restarts=8, max_steps=300, record_every=37
    ),
    execution=EXECUTION,
)

# The comparable column: both rules' own labels, put through the same ceiling.
d_rule_phase = profiled_retention(np.asarray(d_rule.predict_scores(scores)), n_bins)
ds_rule_phase = profiled_retention(np.asarray(ds_rule.predict_scores(scores)), n_bins)
assert ds_rule_phase > d_rule_phase

# The column that does NOT compare: each rule scored on the criterion it optimized.
assert d_rule.train_report is not None
assert ds_rule.train_profiled_report is not None
```

**Two reusable rules, two columns, and only one of them compares.** On phase information, the
same quantity against the same ceiling for both rules, the profiled rule retains
{f("dsRuleProfiledRetention")} against the plain rule's {f("dRuleProfiledRetention")}, and the
profiled rule wins, which is the entire reason it exists. Beside that sits each rule's score on the
criterion it actually optimised: {f("dRuleOwnCriterion")} for the plain rule and
{f("dsRuleOwnCriterion")} for the profiled one. Those two are *not* comparable: the first is the
overall D-efficiency, a geometric mean over both parameters against the full unbinned information,
and the second is phase retention against the profiled ceiling, and they happen to sit close enough
to look like a comparison. Reading that column alone was a real
mistake made while this study was being built, which is why it is spelled out here.

### Other inputs to the same task

The analytic callback is one of several ways into this door, and the others take the same shape.
When the model is a linear combination of known component densities, `LinearComponents` declares
the components and the reference coefficients and the provider derives the sensitivities:

```python
rng = np.random.default_rng(7)


def peak(X):
    return np.exp(-0.5 * ((X[:, 0] - 1.0) / 0.4) ** 2)


def flat(X):
    return np.ones(X.shape[0])


model = sq.LinearComponents(
    components={"peak": peak, "flat": flat},
    coefficients={"peak": 1.0, "flat": 0.5},
    variables=["mass"],
)
component_score = sq.LinearComponentScore(model)
```

With Monte Carlo events rather than a bounded integral, the source carries the measure. A uniform
draw reweighted by the reference intensity is one honest way to build it, and prediction is always
explicit: it takes sensitivities, never raw observations, so the conversion stays a line you wrote.

```python
events = rng.uniform(-2.0, 3.0, size=(2_000, 1))
intensity = np.asarray(model.evaluate_components(events)) @ np.asarray(model.coefficients)

quantizer = sq.fit_quantizer(
    sq.ObservationSample(events, intensity),
    provider=component_score,
    n_bins=5,
    config=sq.DExchangeConfig(seed=11),
)
grid = np.linspace(-2.0, 3.0, 100)[:, None]
grid_bins = quantizer.predict_scores(component_score.score(grid))
```

And when the component matrix is already in memory, `scores_from_components` is the explicit
adapter. It is a conversion rather than a fit, so the task is chosen afterwards, here a fixed-sample
partition rather than a reusable rule:

```python
components = np.asarray(model.evaluate_components(events))
component_scores = sq.scores_from_components(components, model.coefficients)
partition = sq.optimize_partition(
    component_scores, weights=intensity, n_bins=5, config=sq.DExchangeConfig(seed=11)
)
```
