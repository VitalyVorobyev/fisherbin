# A classifier instead of a likelihood

*Who this is for: anyone whose model is a trained classifier rather than a density, who has been handed a number saying how much of the measurement survived, and who wants to know whether to believe it.*

## You have a classifier, not a likelihood

The measurement is a mixture. Events arrive from two sources — call them signal and background —
and the quantity wanted is how much of the sample is signal. If both components' densities could
be written down, everything that follows would be arithmetic. In practice they cannot: the
generator is a simulation, the observable is engineered, and what exists instead is labelled
simulated events for each component and a classifier trained to tell them apart.

That classifier is enough to compress with. Its calibrated output, divided by the proportions it
was trained on, is an estimate of the ratio of the two densities, and a ratio is all the
compression needs — a common factor in both densities cancels out of it.

Then the library hands back a number: this much of the measurement survived the compression. The
question this page answers is whether that number is about your data or about your classifier. The
other pages that reach for a classifier the same way — the cells, the collision events — have no
ground truth to check it against. This one does, because its data was generated on purpose.

## The data, and why it is simulated

This walkthrough uses a synthetic mixture with an analytic truth score. It lets us compare
reported surrogate retention with true-score retention for the same fitted labels. The Michelson
walkthrough also has an analytic model; FlowCyt uses measured cells and HEP uses simulated events.

The mixture is two normal components with different means and different widths, mixed at a signal
fraction of {f("signalFraction")}. Two independent samples come from that mixture:
{f("nTrain")} events to fit the compression on and {f("nTest")} held-out events to evaluate it.
A third and much larger sample of {f("nClosure")} events is drawn from the *balanced* mixture
instead — the measure the density ratios are defined against — and never enters a fit; it exists
so that one diagnostic below has a tight enough noise floor to be worth reading.

There is no third-party data here and no third-party licence. The generator is
`examples/door3_classifier.py`, committed under the same MIT licence as the rest of the library,
and the numbers on this page are read from the evidence file it writes,
`docs/examples/assets/door3-classifier.json`. The exhaustive record — the full ladder, the
per-rung table, the figure, and the discussion of which parts of classifier error cost information
— is the reference page at{" "}
<ReferenceLink to="examples/door3-classifier/">Door 3, classifier-estimated density ratios</ReferenceLink>,
which this page deliberately does not restate.

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

import scorequant as sq
```

```python
signal_mu, signal_sigma = 1.0, 0.5
background_mu, background_sigma = 0.0, 1.5
reference_fractions = (0.3, 0.7)


def draw(seed, n, signal_fraction):
    rng = np.random.default_rng(seed)
    is_signal = rng.random(n) < signal_fraction
    x = np.where(
        is_signal,
        rng.normal(signal_mu, signal_sigma, n),
        rng.normal(background_mu, background_sigma, n),
    )
    return x[:, None]


train_observations = draw(2026, 400, reference_fractions[0])
test_observations = draw(999, 600, reference_fractions[0])
# From the balanced mixture, not the reference one: this is the measure the
# ratios below are declared against, and the closure check must see it.
closure_observations = draw(4242, 50_000, 0.5)
```

## From posteriors to a score

The route from a classifier to a score is three explicit steps, and it helps to run them once by
hand before letting a provider package them.

A calibrated classifier's posteriors are estimates of the component densities weighted by the
proportions it was trained on, so dividing by those proportions leaves the density ratios;
`ratios_from_posteriors` does exactly that division. The mixture parameterization then turns
ratios into the derivative of an event's log likelihood with respect to the mixture fractions —
the score. With two components on the simplex, one is absorbed as the reference, so the score
here has a single coordinate: how strongly this event's likelihood responds to the signal
fraction moving.

```python
def exact_posteriors(x):
    values = np.asarray(x)[:, 0]
    signal = np.exp(-0.5 * ((values - signal_mu) / signal_sigma) ** 2) / signal_sigma
    background = (
        np.exp(-0.5 * ((values - background_mu) / background_sigma) ** 2) / background_sigma
    )
    joint = np.stack([signal, background], axis=1)
    return joint / joint.sum(axis=1, keepdims=True)


grid = np.linspace(-3.0, 3.0, 7)[:, None]
posteriors = exact_posteriors(grid)
ratios = sq.ratios_from_posteriors(posteriors, [0.5, 0.5])
grid_scores = sq.mixture_scores_from_ratios(ratios, list(reference_fractions))
assert grid_scores.shape == (grid.shape[0], 1)

exact = sq.ScoreFunction(
    lambda x: sq.mixture_scores_from_ratios(
        sq.ratios_from_posteriors(exact_posteriors(x), [0.5, 0.5]), list(reference_fractions)
    ),
    provenance=sq.ScoreProvenance(kind="exact", description="analytic Bayes posterior"),
)
assert exact.provenance.exact_fisher is True
```

Those posteriors are the analytic ones, computed from the two densities this simulation was drawn
from. They are the thing a real analysis does not have, and they are why this page can check the
classifier rather than merely warn about it.

## The fit

The classifier is a logistic regression on a quadratic feature, which is enough to reach the exact
boundary between two normals of different width — so the only thing that limits it is how many
labelled events it is given. Start with the hardest case, {f("smallTrainSize")} labelled events
per component:

```python
def make_features(x):
    return np.column_stack([x, x**2])


def train_classifier(seed, n_per_class):
    rng = np.random.default_rng(seed)
    x_signal = rng.normal(signal_mu, signal_sigma, n_per_class)
    x_background = rng.normal(background_mu, background_sigma, n_per_class)
    x = np.concatenate([x_signal, x_background])
    y = np.concatenate([np.zeros(n_per_class), np.ones(n_per_class)])
    return LogisticRegression(max_iter=1000).fit(make_features(x), y)


def classifier_provider(model, description):
    def predict(x):
        return model.predict_proba(make_features(np.asarray(x)[:, 0]))

    return sq.DensityRatioScore.from_classifier(
        predict,
        [0.5, 0.5],
        sq.MixtureParameterization(list(reference_fractions)),
        description=description,
    )


estimated = classifier_provider(
    train_classifier(101, 15), "logistic regression, 15 events per class"
)
quantizer = sq.fit_quantizer(
    sq.ObservationSample(train_observations),
    provider=estimated,
    n_bins=4,
    criterion=sq.DOptimality(),
    config=sq.DExchangeConfig(seed=7),
)
assert estimated.provenance.kind == "estimated_ratio"
assert estimated.provenance.exact_fisher is False
assert quantizer.information_kind == "supplied_score_surrogate"
```

Training and calibration stay application code; the library starts at `predict_proba`, the
proportions the classifier was trained on, and a declared parameterization. The source is an
`ObservationSample`, because these are raw events rather than scores, and it requires a provider
for exactly that reason. `DOptimality` with the exchange solver is held fixed for every fit on
this page, so that nothing varies except the quality of the classifier.

The three assertions above are the library's own bookkeeping, and the middle one cannot be
overridden. `ScoreProvenance.exact_fisher` is a property derived from `kind`, not a field you can
set, so an estimated score cannot claim exact Fisher semantics even by mistake:

```python
try:
    sq.ScoreProvenance(kind="estimated_ratio", exact_fisher=True)
    raise AssertionError("exact_fisher is derived from kind, never accepted as a flag")
except TypeError as error:
    exact_fisher_is_not_a_flag = str(error)
```

## The numbers

Two numbers can be computed about this fit, and only one of them is available in a real analysis.

The first is what the result reports about itself: take the held-out events, score them with the
same classifier, and ask how much of *that* score the bins preserve. The second relabels the same
held-out events with the same fitted rule and then evaluates the *exact* score under those labels
— which is what a downstream fit's precision actually depends on.

```python
estimated_test_scores = estimated.score(test_observations)
surrogate = float(quantizer.evaluate_scores(estimated_test_scores).geometric_mean_retention)

labels = np.asarray(quantizer.predict_scores(estimated_test_scores))
achieved = float(
    sq.information_report(
        np.asarray(exact.score(test_observations)), labels, n_bins=quantizer.n_bins
    ).geometric_mean_retention
)
assert surrogate > 0.95 > achieved

ceiling = sq.fit_quantizer(
    sq.ObservationSample(train_observations),
    provider=exact,
    n_bins=4,
    criterion=sq.DOptimality(),
    config=sq.DExchangeConfig(seed=7),
)
assert ceiling.information_kind == "exact_fisher"
```

## What that means for your analysis

The reported number is a statement about the vectors the library was handed, not about the world.
It says the bins preserve the classifier's opinion; it cannot say whether the classifier's opinion
is right, because nothing in the compression step ever sees the truth. With a poorly trained
classifier the reported number stays high and comfortable while the measurement it describes has
quietly lost much more than advertised. With a well-trained one the two converge, and
the comfort becomes justified.

So the reported retention should be read as bounded by how much you trust the classifier: it is
what the compression achieved on the score it was handed, and the distance from there to what you
actually have stays unmeasured unless you measure it. When a check is possible — an exact score, a
better-estimated one, a corner of the space where the answer is known — the way to run it is the
one above: relabel a held-out sample with the fitted rule, then evaluate the better score under
those labels. When no check is possible, the number is still useful and still honest about what it
is; that is why the result carries `{f("classifierInformationKind")}` rather than a claim of exact
Fisher information.

## What the reported number would have told you

There are two defaults worth measuring against here, and this page has to answer both. The first
is the one a practitioner reaches for without thinking: accept the self-report. The second is the
one every other walkthrough compares against: bin the score with a simple one-dimensional rule
instead of fitting a partition to it.

Take the second one first, because the answer is not the flattering one.

This is the honest boundary of the method, and it is why it is worth reading the other three
walkthroughs. The gap that makes fitting worth doing opens up when the score has more than one
coordinate and the informative direction is not any one of them — HEP's six-bin comparison moves
retained profiled information by an order of magnitude more than the difference measured here,
and the Michelson page has a natural-looking one-dimensional rule that retains nothing at all
because it aliases. One dimension and a smooth score is the case where you do not need this
library.

So the interesting comparison on *this* page is not between two binnings. It is between the two
things a single binning can be said to have retained.

## The check that catches it, and the way to get it wrong

There is a diagnostic that flags this without an oracle. Exact density ratios integrate to one
under the measure they are defined against, so averaging the estimated ratios over a sample from
that measure and looking at the deviation is a direct test of the estimator, available before any
fit. `ratio_closure_report` computes it.

```python
estimated_closure = sq.ratio_closure_report(
    estimated.ratio(closure_observations), np.ones(closure_observations.shape[0])
)
exact_closure = sq.ratio_closure_report(
    sq.ratios_from_posteriors(exact_posteriors(closure_observations), [0.5, 0.5]),
    np.ones(closure_observations.shape[0]),
)
# The same exact ratios, averaged over the reference mixture instead: the wrong
# measure for this check, and a perfect score fails it.
wrong_measure = sq.ratio_closure_report(
    sq.ratios_from_posteriors(exact_posteriors(train_observations), [0.5, 0.5]),
    np.ones(train_observations.shape[0]),
)
assert exact_closure.max_residual < estimated_closure.max_residual
assert wrong_measure.max_residual > 50 * exact_closure.max_residual
```

The check works, and the ordering above is it working: the residual falls monotonically with
classifier quality and the exact provider sits below every rung. Note honestly that against the
best-trained rung it sits below only barely, because at {f("largeTrainSize")} labelled events per
class the classifier's residual bias has already reached the same order as the noise floor of a
{f("nClosure")}-event sample.

The trap is the last row. The residual is joint in three things — the estimator, the proportions
declared for it, and the *measure the average is taken over* — and only the first is what anyone
is looking for. These ratios are declared against the balanced mixture the classifier was trained
on. Average them over the reference mixture instead, which is the sample an analysis already has
lying around, and the check returns {f("wrongMeasureResidual")} for a *perfect* score. That is not
a smaller bias or an unreliable diagnostic: under the reference measure the exact ratios average
to {f("analyticSignalRatioMean")} and {f("analyticBackgroundRatioMean")} rather than to one, and
the check is reporting that, accurately, in answer to a question nobody meant to ask. It is an
easy substitution to make, the symptom is a large residual that does not improve as the classifier
does, and this page keeps both numbers side by side so it can be recognised rather than
mistrusted.

## The same door, other inputs

Not every parameter is a mixture fraction. When the parameter shifts the density instead — a mass,
a scale, a calibration constant — the classifier that estimates a ratio is one trained to separate
events generated slightly below the reference value from events generated slightly above it. Its
log odds estimate the directional log density ratio, and the central difference of that, divided
by the spacing, is a score estimate. `CentralLogRatioScore` takes the paired probabilities in
minus, plus order and does the subtraction and the division.

```python
delta = 0.1


def central_probabilities(x):
    plus = 1.0 / (1.0 + np.exp(-2.0 * delta * np.asarray(x)[:, 0]))
    return np.stack([1.0 - plus, plus], axis=1)


central = sq.CentralLogRatioScore(central_probabilities, [delta], [0.5, 0.5])
recovered = np.asarray(central.score(grid)).ravel()
assert np.allclose(recovered, grid.ravel())

location_rng = np.random.default_rng(0)
central_quantizer = sq.fit_quantizer(
    sq.ObservationSample(location_rng.normal(size=(1_000, 1))),
    provider=central,
    n_bins=4,
    config=sq.DExchangeConfig(seed=13),
)
assert central_quantizer.information_kind == "supplied_score_surrogate"
```

The classifier in that fence is the exact Bayes rule for a Gaussian location model, whose score is
the observation itself, so `recovered` reproduces it to floating-point accuracy — which is the
sanity check worth running against your own callback before trusting a fit built on it. And the
result is still labelled a surrogate, because the constructor was told the probabilities came from
a classifier. That labelling is the point of this page: it is not a warning attached to the
output, it is a consequence of what the input was declared to be.
