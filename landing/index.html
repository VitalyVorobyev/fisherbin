Information-preserving hard binning for parameter estimation

ScoreQuant is a Python library. Given a weighted sample of events and the statistical model whose parameters you will estimate from their counts, it assigns each event to one of a few hard labels by maximizing a matrix criterion of the Fisher information that survives the labelling — D-optimality, normalized trace, or profiled Ds when nuisance parameters are present — and reports the retained fraction as a number. It separates the fixed-sample task (label this table) from the reusable-rule task (a quantizer applied to future events), certifies when a solver's optimum is exchange-stable, and records the provenance of scores that were estimated by a classifier rather than derived from a model.

uv add scorequant or pip install scorequant Python 3.12 or newer. JAX by default; NumPy as the portable runtime. Whether to enable 64-bit floats is your application's choice, never the library's.

The identity the method rests on

Write each event's local sensitivity as its score, the gradient of its log-likelihood in the parameters. The unbinned Fisher information is the second moment of the score. A hard rule that sends each event to one of the labels keeps only the between-cell part, and the difference is the within-cell scatter of the score. Binning can therefore only lose information, and the loss depends on how the score varies inside a cell, not on how the measurement does. ScoreQuant optimizes the partition in score space, where this identity is written, so the loss becomes a quantity you choose and report instead of one you inherit from axis ticks.

The smallest fit

import numpy as np
import scorequant as sq

rng = np.random.default_rng(3)
scores = rng.normal(size=(2_000, 2))

partition = sq.optimize_partition(
    scores,
    n_bins=5,
    criterion=sq.DOptimality(),
    config=sq.DExchangeConfig(seed=3),
)
stable = bool(partition.exchange_stable)
efficiency = float(partition.train_report.geometric_mean_retention)

optimize_partition labels the rows it was given and nothing else. When a rule for events you have not seen is what you need, fit_quantizer returns one with an explicit predict_scores. Which task you have is the first decision, and Choosing your workflow walks through it; the same fit with its printed output and the meaning of each number is on Get started.
